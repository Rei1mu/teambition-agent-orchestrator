TBA 任务流程

agent 只写任务备注 · 评论留给你 · ask 会一直等你，会话不会自己断

主流程

你说一句「开工」
在已接入的项目目录里发这句话。没接入过的目录第一次发 tba g。
四个名字完全等价： tba g tba go tba r tba run
agent跑 tba g（或 go / r / run）
按当前目录找项目，按退出码决定下一步。
退出 3 · NO_BINDING停。目录没绑项目，也不在 git 仓库里。不领任务、不建项目。
退出 4 · NO_PROJECT问你要不要初始化。你同意后跑 tba ensure-project。
退出 5 · BLOCKED停。手上有「在等回复但没人接」的任务。先 tba wait 接回来，或 tba release 退回队列。
退出 0 · EMPTY停。队列空，没活。
退出 0 · claim_id领到任务。任务自动转「进行中」+ 看板列「进行中」。
agent读项目记忆
tba memory --project <id> — 上次踩过的坑、做过的决策，先看一遍。
agent干活
改代码、查资料、跑命令。长操作前后各跑一次 tba beat <claim> 续命，否则会被判会话断开。
agent过程写进备注
tba note <claim> --text "..." — 往后追加，带时间戳。不写评论。
agent写完，交回给你
两步不许省：
① note结论写进备注：改了什么、怎么验。
② ask --done标准三选项提问。任务转「待回复」+ 列「待回复」，自动发邮件，然后就地阻塞等你回数字——这条命令不返回，会话就不会断。
单轮 540 秒没等到 → 退出码 2 → 改用 tba wait <claim> 接着等（别重跑 ask，会重发信）。agent 不许结束会话。
540 / 15 / 20 秒都是默认值，设置页「等待与轮询」可改，也可直接改 data/config.toml。
你在 Teambition 评论或邮件里回复
两条路都行：网页评论，或者直接回那封邮件（保留主题）。
数字最省事：回 0 收尾、1 先写记忆再收尾、2 继续改。回文本也完全可以，tba 判不了数字就原样交给 agent 理解。
不回也安全——「待回复」永不超时，放多久都行。
tba按数字直接动作
不让 agent 解释数字再执行——这是流程，不是判断。
结束只有 0 收尾
转「已解决」+ 列「已解决」。其余数字一律回「进行中」+ 列「进行中」，接着干。

回复方式：数字最省事，文本也行

网页评论和邮件回信走同一条路（邮件回信会被写成评论）。数字只是最省事的写法，不是唯一写法。

两个通道，各管一边

任务备注（note）

只有 agent 写。过程、结论、提问都在这。往后追加，带时间戳，不覆盖你写的原始需求。

网页任务详情第一屏可见。

任务评论

只有你写。回数字、回文本、补说明都行。邮件回信也会被写成评论，落在这里。agent 一律不写。

评论里只有你的话，wait 不用猜某条是谁发的。

当回复处理
什么时候发
只有 ask 发信。配置 mail_on_ask（默认开）。note / report 不发。
主题带标记
主题形如 [TB clm-xxxx] 需要你回复：任务名。回信必须保留这个主题，否则认不出是哪条任务。
正文带完整备注
邮件正文 = 问题 + 完整任务备注。你在外面收信就能看到 agent 改了什么、结论是什么，不用跳回网页。
回信怎么进来的
ask 内置的等待每 20 秒轮询一次信箱，把回信写成任务评论，之后完全复用「读评论」逻辑，不搞第二套状态机。
发信失败 / 重发
失败会写进任务备注（⚠ 邮件通知没发出去），不再静默。tba mail resend <claim_id> 只重发通知，不动任务状态。
必须配 IMAP
SMTP 只能发，收不到回信。只配 SMTP 时邮件是单向通知，你回信没人读。

兜底

禁止丢后台
文案写死「ask 前台阻塞，禁止 run_in_background」。丢后台 = 命令在跑但会话结束了，没人接你的回复。
等待中断 → 阻断
ask 每 15 秒写一次 data/waits/ 心跳，进程被杀就停更，60 秒没刷新判「没人接了」。这时 tba inbox 标 ⚠ 等待中断，tba g 返回 BLOCKED（退出码 5），先处理掉才能领新任务。
ask 就地阻塞（主机制）
ask 问完不返回，一直等到你回数字。会话挂着，不会断——这是「不许 agent 自己结束」的核心。
ask 单轮超时
540 秒返回退出码 2，改用 tba wait <claim> 接着等（别重跑 ask，会重发信）。任务状态不变，会话不断。
列1 强制重接
任务被拖到列1，不管台账里是什么状态，一律接管：旧 claim 标 reverted，新建一条。这是「断了怎么恢复」的答案——不依赖任何宿主能力，拖回去就行。
wait 自愈
手动跑 tba wait 而没 ask 过，tba 自动补一次：问题写备注 + 转「待回复」+ 发邮件。配置 wait_auto_ask 可关。
待回复永不超时
挂在「待回复」的任务不参与心跳回收。放多久都安全，回来接着回数字。
心跳超时退回
「进行中」超过 heartbeat_timeout_secs（默认 300 秒）没续命，自动退回「未完成」+ 列 1。这是故意的：连 ask 都没跑就断了的会话，不该占着任务。
退出码 3
你在网页上手动收尾了（改状态 / 拖到列 4-5），agent 收到 3 就停，不会误判。
